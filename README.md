# VNYL — Music Recommendation System

A personalized music recommendation platform built on top of the
[Embeat 45M Spotify Tracks](https://huggingface.co/datasets/GD-Studio/embeat_45m_spotify_tracks)
dataset.

> **Current phase:** Data Engineering Foundation (Steps 1–8)
>
> We are deliberately building this project incrementally.
> The recommendation model, FAISS, collaborative filtering, and all
> downstream systems will be added in later phases.

---

## Initial Dataset Pipeline

```text
45M source dataset (Hugging Face)
        ↓
Hugging Face streaming (no full download)
        ↓
1M initial tracks (sequential sampling)
        ↓
Parquet (incremental write via PyArrow)
        ↓
Validation (row counts, duplicates, missing values, statistics)
        ↓
Exploration (Jupyter notebook with distributions & correlations)
```

## Quick Start

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd VNYL_music_recommendation
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate it:

- **Windows:**
  ```bash
  venv\Scripts\activate
  ```
- **macOS / Linux:**
  ```bash
  source venv/bin/activate
  ```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Authenticate with Hugging Face

The dataset is hosted on Hugging Face and may require you to accept
access conditions before downloading.

1. Create or log in to your [Hugging Face account](https://huggingface.co/).
2. Visit the [dataset page](https://huggingface.co/datasets/GD-Studio/embeat_45m_spotify_tracks)
   and **accept the access conditions** if prompted.
3. Create an access token at <https://huggingface.co/settings/tokens>
   (a *Read* token is sufficient).
4. Authenticate locally:

```bash
hf auth login
```

> **⚠ Never commit your token to Git.**
> The `hf auth login` command stores your token securely in
> your system's credential store. Do not put tokens in `.env`, source
> code, or any file tracked by Git.

### 5. Inspect the dataset

Verify that your authentication and network connection work:

```bash
python src/data/inspect_dataset.py
```

This streams 5 sample records and prints the schema.

### 6. Extract the 1M-song dataset

```bash
python src/data/sample.py
```

This will:

- Stream records from the 45M dataset (no full download)
- Write records in chunks of 10,000 to `data/processed/songs_1m.parquet`
- Print progress every 10,000 rows
- Validate the output file after extraction

Expect this to take **30–90 minutes** depending on your connection speed.

### 7. Explore the dataset

```bash
jupyter notebook
```

Open `notebooks/01_dataset_exploration.ipynb` and run the cells to see:

- Dataset shape and dtypes
- Missing value analysis
- Duplicate analysis
- Numerical feature distributions (histograms)
- Correlation heatmap

## Key Design Decisions

| Decision | Rationale |
|---|---|
| **Streaming mode** | The source dataset is ~45M rows / ~9.5 GB. We never load it all into memory. |
| **Chunked writing** | Records are written to Parquet in 10K-row chunks via `pyarrow.ParquetWriter` to limit peak memory usage. |
| **Sequential sampling** | For the initial version, we take the first 1M records. The code is structured so the sampling strategy can be swapped later. |
| **No aggressive cleaning** | We measure data quality (duplicates, missing values) but do not delete rows yet. Cleaning decisions will be made in a later phase. |
| **No checkpointing** | Adding resumable checkpoints would add significant complexity. If interrupted, delete the partial file and re-run. |
